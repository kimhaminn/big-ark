# 5주차 실습 — 칸과 칸을 잇는다 (M1)

> 오늘은 **처음으로 무엇인가가 흐른다.** 지난 넉 주 동안 칸을 열었는데 안은 비어 있었다.
> 90분 뒤에 **여러분이 쏜 값이 지난주에 만든 Kafka 토픽에서 나와야 한다.** 그것이 오늘의 마일스톤 **M1** 이다.

★ **오늘 새로 설치하는 것은 없다.** 브로커 이미지 하나를 받고, **나머지는 전부 그 컨테이너 안에 이미 들어 있는 명령**으로 한다.

---

## 오늘의 기준은 둘이다

| | 무엇 |
|---|---|
| **동작** | **M1** — 시뮬레이터가 쏜 값이 Kafka 소비자에 나오는가 |
| **판단** | **P2 설계서** — 축 순서에 근거가 있는가 / **P4 봉인 답안** — 무엇을 왜 두지 않는가 |

> **동작만 되고 설계서가 비어 있으면 통과가 아니다.** 지난 넉 주와 같은 기준이 그대로 살아 있다.

---

## 먼저 열어 둘 것

- 지난주(4주차) **토픽 설계서** — 여기 적어 둔 **Kafka 토픽 이름**을 오늘 쓴다
- 지난주에 만든 `docker-compose.yml` — **새로 만들지 않는다. 여기에 한 칸 더한다**

---

## 브로커 이미지

```
eclipse-mosquitto:2
```

수십 MB 다. 지난주 Kafka 이미지보다 훨씬 작다.

## P0 · 지난주 것을 확인하고, 조감 노트를 다시 편다 (10분)

**① 지난주 브로커가 살아 있는가**

```bash
docker compose ps
```

`broker` 가 안 보이면 올린다.

```bash
docker compose up -d broker
```

**② 지난주 정한 Kafka 토픽 이름을 찾는다**

설계서에서 찾는다. **못 찾으면** 브로커에게 직접 묻는다.

```bash
docker compose exec broker /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --list
```

> ★ **찾았으면 설계서에 적어 넣는다.** 다음 주에도 쓴다. **왜 문서를 남기는지가 지금 이 순간이다.**

**③ 조감 노트를 다시 편다**

1주차에 받았던 **조감 노트 빈 양식**을 다시 받는다.

- **지금 채울 수 있는 칸에 ○**
- **아직 모르겠는 칸에 ×**
- **5분을 넘기지 않는다.** 정확하게 채우는 것이 목적이 아니다

> 모르는 칸을 비워 두는 것도 기록이다. **1주차에 몰랐던 것 중 지금도 모르는 것**이 무엇인지가 오늘 확인하려는 것이다.

**④ 남은 마일스톤**

오늘 **M1(수집)** 이 닫힌다. 남은 것은 **M2(8주 · 저장) · M3(11주 · 서빙·관측) · M4(12주 · 완성)** 다.

**완료** — 브로커가 떠 있고, **Kafka 토픽 이름을 손에 들었다.**

> **지난주 미완인 사람은 지금 말한다.** P3 가 지난주 브로커 위에 붙으므로 넘기면 두 배로 든다.

## P1 · 브로커를 하나 더 올린다 (15분)

★ **여기서 두 번 막힌다.** 막히는 것이 오늘 배울 것이므로 **당황하지 않는다.**

**① 구성 파일에 블록을 더한다**

지난주 파일의 `services:` 아래에 붙여 넣는다.

```yaml
  mosquitto:
    image: eclipse-mosquitto:2
    container_name: tfds-mqtt
    ports:
      - "1883:1883"                       # MQTT 표준 포트
    volumes:
      - ./mosquitto.conf:/mosquitto/config/mosquitto.conf
```

> ★ **볼륨이 하나뿐이고 데이터 볼륨이 없다.** 지난주 브로커에는 `broker-data` 를 뒀는데 여기는 없다. **왜 없는지는 P4 에서 묻는다.**

**② 설정 파일 없이 한 번 올려 본다**

먼저 `mosquitto.conf` 를 **만들지 말고** 그냥 올린다. (`volumes:` 줄 두 개를 잠시 `#` 로 막는다.)

```bash
docker compose up -d mosquitto
docker compose logs mosquitto
```

로그에 **브로커가 어느 주소에 붙었는지**가 찍힌다. **그 줄을 읽는다.**

이제 호스트에서 붙어 본다.

```bash
docker compose exec mosquitto mosquitto_sub -h localhost -t 'test/#' -v
```

컨테이너 **안에서는** 붙는다. 그런데 **밖에서는** 안 붙는다.

> **왜 그런가.** `ports:` 를 열었는데 왜 안 되는가. — **포트 매핑은 호스트와 컨테이너를 잇는 것이지, 컨테이너가 안 듣고 있는 주소를 만들어 주지 않는다.** 로그에 찍힌 주소를 다시 본다.

**③ 설정 파일을 얹는다**

`docker-compose.yml` 과 같은 자리에 `mosquitto.conf` 를 만든다. **한 줄만** 쓴다.

```conf
listener 1883
```

`volumes:` 주석을 풀고 다시 올린다.

```bash
docker compose up -d mosquitto
docker compose logs mosquitto
```

★ **이번엔 붙기는 하는데 거부된다.** 로그를 읽으면 이유가 나온다.

> **왜 그런가.** 리스너를 열지 않았을 때는 익명 접속이 허용됐는데, **리스너를 여는 순간 그 기본값이 뒤집힌다.** 바깥에 열린 브로커가 인증 없이 서 있는 상태를 **실수로 만들 수 없게** 한 설계다.

한 줄을 더한다.

```conf
listener 1883
allow_anonymous true
```

> ★ **두 줄이 두 개의 결정이다.** 리스너 개방과 익명 허용은 원래 별개인데, **첫 결정을 하는 순간 두 번째의 기본값이 안전한 쪽으로 옮겨간다.**
>
> **참고** — 이미지 안에 `/mosquitto-no-auth.conf` 라는 파일이 들어 있다. 그것을 지정하면 두 줄을 안 써도 열린다. **오늘은 쓰지 않는다.** 다만 **파일 이름이 `no-auth` 라는 것**을 눈에 담아 둔다. 인증 없는 구성을 쓰려면 **이름에 그렇게 적힌 것을 골라야 한다.**

**④ 호스트에서 붙는다**

```bash
docker compose exec mosquitto mosquitto_sub -h localhost -t 'test/#' -v
```

**완료** — 명령이 **끝나지 않고 그대로 멈춰 있으면** 통과다. 구독이 붙어서 기다리는 중이다. `Ctrl+C` 로 빠져나온다.

### 판단 — 답할 수 있어야 한다

> **리스너 개방과 익명 허용은 왜 별개 결정인가. 그런데 브로커는 왜 하나를 켜면 다른 하나를 잠그는가.**
>
> **오늘 둘 다 여는 대가는 무엇인가. 실습실 PC 라서 괜찮은 이유는 무엇인가.**

### 막혔을 때 — 순서대로 본다

| 증상 | 먼저 볼 것 |
|---|---|
| 컨테이너가 안 뜬다 | `docker compose logs mosquitto` — 설정 파일 문법 오류일 때가 많다 |
| 밖에서 안 붙는다 | 로그의 **바인딩 주소.** `listener` 줄이 실제로 먹었는가 |
| 붙자마자 끊긴다 | `allow_anonymous true` 가 있는가 |
| 설정이 안 먹는다 | 마운트 경로가 `/mosquitto/config/mosquitto.conf` 가 맞는가 |

## P2 · 토픽 계층을 설계한다 (25분) ★오늘의 중심

**칠 명령이 거의 없다.** 오늘 채점하는 것은 **왜 그렇게 갈랐는가**이고, 그것은 명령으로 확인되지 않는다.

**① 축을 나열한다**

무엇으로 가를 수 있는가. 후보를 다 적는다.

- 현장(터널) · 구역 · 장비(리피터) · 센서 종류 · 데이터 성격(원시 / 판정)

**② 순서를 정한다** ★

같은 축을 써도 **순서가 다르면 자를 수 있는 것이 다르다.**

```
tfds/t02/temp        ← 현장이 앞
tfds/temp/t02        ← 센서 종류가 앞
```

- 앞이 **현장**이면 → `tfds/t02/#` 로 **터널 하나만** 뽑을 수 있다
- 앞이 **센서 종류**면 → `tfds/temp/#` 로 **온도만** 뽑을 수 있고, **터널 하나만은 구독 하나로 못 한다**

**③ 구독 문장 3개를 함께 쓴다**

토픽 형태만 적으면 축 순서의 결과가 안 보인다. **`+`·`#` 를 쓴 구독 예 3개**를 반드시 함께 적는다.

**④ 설계서로 남긴다**

`토픽계층설계서_양식.md` 를 리포지토리의 **결정 기록 자리**에 복사해 채운다.

### 먼저 셀 것 — 소비 계통이 몇인가

TFDS-Edu 는 원시 토픽에 **3계통**이 붙는다 (경량 처리 · 시계열 적재 · 원본 아카이브).

> **구독자가 무엇을 걸러야 하는지**가 축 순서를 정한다. **소비 쪽을 먼저 세고 나서 토픽을 가른다.**

### 강의에서 본 셋을 베끼지 않는다 ★

세 시스템의 토픽 설계가 전부 달랐다. **셋 다 자기 조건에서 나온 답**이고 여러분의 조건은 또 다르다. **가장 정교해 보이는 것을 고르는 것이 가장 흔한 실수다.**

### 판단 — 답할 수 있어야 한다

> **센서가 12종이라고 토픽을 12개로 가르지 않는 이유는 무엇인가.** (지난주 Kafka 에서 받은 질문과 답이 다르다 — MQTT 는 계층이라 **가르는 비용이 낮다.** 그래서 더 조심해야 한다.)
>
> **앞에 둔 축으로만 자를 수 있다면, 무엇을 앞에 두어야 하는가.**

**완료 판정** — **축 순서에 근거를 대고, 구독 예 3개가 그 순서의 결과로 설명된다.** 계층 수는 통과 조건이 아니다.

## P3 · 브리지를 만든다 (25분) ★★ M1 이 닫힌다

**① 먼저 구독을 건다** — 터미널 1

```bash
docker compose exec mosquitto mosquitto_sub -h localhost -t 'tfds/#' -v
```

`-v` 는 토픽 이름을 함께 보여준다. **이 터미널은 그대로 둔다.**

**② 발행한다** — 터미널 2

```bash
docker compose exec mosquitto mosquitto_pub -h localhost \
  -t 'tfds/t02/temp' -m '{"v":41.2}'
```

터미널 1에 나오면 된다.

**③ 순서를 바꿔 본다** ★

터미널 1의 구독을 `Ctrl+C` 로 끊는다. 그 상태에서 ②를 몇 번 친다. 그리고 다시 구독을 건다.

> **아무것도 안 나온다.** 구독자가 없는 동안의 메시지는 **그대로 지나갔다.**
>
> ★ **이것이 오늘 강의에서 「흘려보낸다」고 한 것의 실물이다.** MQTT 는 이름과 달리 **기본적으로 큐가 아니다.**

**④ 파이프로 잇는다** — 터미널 1 (브리지)

```bash
docker compose exec -T mosquitto mosquitto_sub -h localhost -t 'tfds/#' \
  | docker compose exec -T broker /opt/kafka/bin/kafka-console-producer.sh \
      --bootstrap-server localhost:9092 --topic <지난주에 정한 이름>
```

> `-T` 는 터미널을 붙이지 말라는 뜻이다. **파이프로 이을 때는 이게 있어야 한다.**
>
> ★ **브리지가 이게 전부다.** 왼쪽이 구독하고, 오른쪽이 프로듀스한다. 그 사이의 `|` 하나가 브리지다.

**⑤ 반대쪽에서 받는다** — 터미널 3

```bash
docker compose exec broker /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 --topic <지난주에 정한 이름> --from-beginning
```

**⑥ 시뮬레이터를 만든다** — 터미널 2

```bash
while true; do
  docker compose exec -T mosquitto mosquitto_pub -h localhost \
    -t 'tfds/t02/temp' -m "{\"v\":$((RANDOM % 60))}"
  sleep 2
done
```

**완료 — ★ M1** — 터미널 3에 값이 계속 나오면 오늘의 마일스톤이 닫혔다.

### 끊었다 이어 본다 ★

터미널 1(브리지)을 `Ctrl+C` 로 끊는다. 시뮬레이터는 그대로 둔다. 10초쯤 뒤에 브리지를 다시 띄운다.

> **그동안 쏜 값은 Kafka 에 없다.** 브리지가 없는 동안 MQTT 쪽에서 지나갔고, 아무도 붙잡지 않았다. **이 구멍을 P4 에서 다룬다.**

### 막혔을 때

| 증상 | 먼저 볼 것 |
|---|---|
| 파이프에서 아무것도 안 나온다 | `-T` 를 붙였는가. 없으면 파이프가 안 먹는다 |
| 토픽을 못 찾는다고 나온다 | 지난주 이름이 맞는가. `kafka-topics.sh --list` 로 확인 |
| 구독은 되는데 Kafka 에 안 들어간다 | 터미널 3의 `--from-beginning` 을 빼고 다시. 이미 지나간 것을 보고 있을 수 있다 |
| `while` 문이 안 돈다 | 한 줄로 붙여 친다 — `while true; do ...; sleep 2; done` |

## P4 · 무엇이 번역되지 않았는가 (15분)

**방금 만든 브리지가 하지 못한 것**을 찾는다. 이것이 오늘의 마지막 산출물이다.

**① 키가 없다**

터미널 3을 끊고 **파티션을 보이게** 다시 띄운다.

```bash
docker compose exec broker /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 --topic <지난주에 정한 이름> \
  --property print.partition=true --from-beginning
```

> **메시지가 파티션에 흩어진다.** 지난주에 정한 키 규약이 **지켜지지 않는다.** 파이프는 키를 만들 방법이 없다.

**② 유실 구간이 있다**

P3 에서 이미 봤다. 브리지를 재기동하면 그 사이가 비어 있다.

**③ 원문이 그대로 간다**

Kafka 쪽에 온 값을 본다. **MQTT 토픽 문자열이 없다.** `tfds/t02/temp` 에서 왔다는 것이 어디에도 안 남았다.

**④ 셋 중 지금 채워야 하는 것이 있는가** ★

**무기명으로 적어 낸다.** 봉인 답안 양식을 쓴다.

> **셋 중 지금 채워야 하는 것이 있는가. 있다면 무엇이고, 없다면 왜 없는가.**

★ **「없다」가 정답일 수 있다.** 지금 규모(시뮬레이터 하나, 확인용 소비자 하나)에서는 셋 다 아직 문제가 되지 않는다. **그것을 근거를 대고 말할 수 있는가**가 오늘 마지막으로 묻는 것이다.

★ **반대 방향도 함께 생각한다** — 채우려면 브리지가 **상태를 갖게 되고**, 그 순간 재기동·재처리의 책임이 하나 는다.

**한 줄 더** — P1 에서 **볼륨을 두지 않은 것**이 ②와 어떻게 이어지는지 적는다.

**완료 판정** — 봉인 답안에 **셋 중 무엇을 왜 두지 않는지**가 적혀 있다. 「다 채워야 한다」도 근거가 있으면 통과다.

## 오늘 남는 것 — 다음 주에 그대로 쓴다

| 무엇 | 어디 |
|---|---|
| `mosquitto` 서비스 블록 + `mosquitto.conf` | 리포지토리. **내리지 않는다** |
| ★ **MQTT 토픽 계층 설계서** | 결정 기록 자리. **다음 주 소비자가 이 토픽을 구독한다** |
| ★ **브리지 명령 1줄** | 설계서에 **함께 적어 둔다.** 잃어버리면 파이프라인이 끊긴다 |
| 봉인 답안 | 강사 회수 |
| 조감 노트 재기입본 | 강사 회수 |

> **오늘 정한 토픽 계층과 브리지 명령은 다음 주에 그대로 쓴다.** 설계서를 잃어버리지 않는다.

| 구독 | `mosquitto_sub -h localhost -t 'tfds/#' -v` |
| 발행 | `mosquitto_pub -h localhost -t 'tfds/t02/temp' -m '{"v":41.2}'` |
| 브리지 | `… exec -T mosquitto mosquitto_sub …` **`|`** `… exec -T broker kafka-console-producer.sh …` |
| 적재 확인 | `kafka-console-consumer.sh … --topic T --from-beginning` |
| 파티션 보기 | `kafka-console-consumer.sh … --property print.partition=true` |
| 토픽 목록 | `kafka-topics.sh … --list` |

### 명령이 길 때 — 별칭을 만든다

```bash
alias mq='docker compose exec mosquitto'
alias kf='docker compose exec broker /opt/kafka/bin'
```

그러면 `mq mosquitto_sub -h localhost -t 'tfds/#' -v` 로 줄어든다. **파이프에는 `-T` 가 필요하므로 별칭을 따로 둔다.**

```bash
alias mqT='docker compose exec -T mosquitto'
alias kfT='docker compose exec -T broker /opt/kafka/bin'
```
